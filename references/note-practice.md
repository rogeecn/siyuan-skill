# 最佳笔记实践（Best Practices for Notes in SiYuan）

> 这份文档回答一个问题：**什么样的笔记习惯，能在半年后仍然有用？**
> 结论来自 5 个公开实践案例 + 2 篇反例分析，并落成可以直接在 SiYuan 里执行的规则与配方（含 CLI 命令）。
> 语法细节见 `siyuan-markdown.md`，端点细节见 `siyuan-api.md`，能力边界见 `limitations.md`。

## 0. 五条底线（先看这个）

1. **收集不算学习。** 存下来只给了你「进步的感觉」——`The collector's fallacy`：知道有这回事 ≠ 掌握这件事。
2. **每条笔记自己站得住。** 脱离上下文、脱离原文、脱离当时的对话，一年后的你还看得懂吗？
3. **先写标题，再写内容。** 标题是笔记的 API：一个完整短语，别人（和未来的你）能直接引用它。
4. **链接是为了复述，不是为了连成图。** 一条链接背后要有一句「为什么它俩相关」。
5. **输出倒逼输入。** 没有产出计划的笔记库会退化成收藏夹。

## 1. 案例速览：别人怎么做的

| 案例 | 做法 | 可以直接抄的一条 |
| --- | --- | --- |
| 卢曼卡片盒 / 吕立青（[链接](https://blog.jimmylv.info/2020-06-03-zettelkasten-in-action/)） | 三类卡：文献卡（用自己的话）→ 参考卡（补来源）→ 永久卡（与既有想法对话）。卢曼靠它写了 70 多本书、400 多篇论文 | **文献卡必须用自己的话写**，复制粘贴等于没读 |
| Andy Matuschak 常青笔记（[链接](https://notes.andymatuschak.org/zDh1yhNFQNxDEre12B4zd8k)） | 标题即 API；分离关注点（一卡一意）；标题用完整断言；正面表述 | 标题写成**判断句**：「块引用比标签更适合表达关系」，而不是「块引用笔记」 |
| Tiago Forte / PARA + GTD 案例（[链接](https://fortelabs.com/blog/second-brain-case-study-how-a-gtd-master-trainer-uses-para/)） | 按「可执行性」而非主题组织：Projects / Areas / Resources / Archive；与 GTD 的下一步行动、每周回顾打通 | **项目结束时归档**，否则库会变成垃圾场 |
| 少数派 xuezhao 的思源写作流（[链接](https://sspai.com/post/87171)） | 思源当「数据仓库」：碎片进 DailyNotes 靠双链串联；非碎片直接进领域/专题文档；写作时新建主题文档→列大纲→用反链召回素材→重组 | **碎片永不单独建档**，先落在当天，再被反链捞出来 |
| Tiago Forte 渐进式总结（[链接](https://sspai.com/post/69025)） | 分层浓缩：原文（只留来源）→ 摘要（必做）→ 加粗/高亮 → 一句话精华 | 每层都保留「可发现性」，别把原文删干净 |
| 反例：收集者谬误（[链接](https://memo.d.foundation/topics/writing/collectors-fallacy)） | 收集行为本身有短反馈，制造进步错觉 | 收藏前先问：**我打算什么时候用它？** 答不出就不收 |
| 反例：信息焦虑（[链接](https://weichen.blog/not-the-answer/)） | 「我以为自己想清楚的事，写下来才发现没真正理解」 | 判断标准不是「存了多少」，而是**能不能不看原文讲一遍** |

## 2. 推荐架构：四层，别多加

```
① 采集层  DailyNotes（当天一切碎片）+ 收件箱文档
     ↓ 每天/隔天 30 分钟
② 孵化层  原子卡（一篇一意，标题是断言）
     ↓ 每周回顾时挂载
③ 结构层  领域/专题文档（MOC：地图而非仓库），数据库（项目/任务/书单）
     ↓ 需要产出时
④ 输出层  主题文档 → 大纲 → 召回素材 → 成稿 → 归档
```

**为什么只有四层**：层数越多，搬迁成本越高。每多一层，你就多一个「该放哪」的决策点，而决策成本是笔记系统死亡的第一原因。

**DAG 原则**：采集层可以乱，结构层必须收敛。任何一条笔记最多经历「碎片 → 卡 → 挂到某个 MOC」两次搬迁，不允许三次以上。

## 3. 命名与标识规范

| 对象 | 规则 | 理由 |
| --- | --- | --- |
| 领域文档 | `领域·写作`、`领域·健康` | `·` 不参与层级，避免被当成路径 |
| 专题/MOC | `MOC·知识管理` | 一眼区分「地图」与「内容」 |
| 原子卡 | 完整断言句：`块引用比标签更适合表达关系` | 标题即 API，可被 `(( ))` 引用成自然语言 |
| 日记 | 保持内核默认（`YYYY-MM-DD`，`hpath=/daily note/YYYY/MM/YYYY-MM-DD`） | 自动创建、可被 `custom-dailynote-<日期>` 定位 |
| 数据库 | `项目看板`、`书单` | 数据库是视图，不要用日期命名 |
| 文件名/标题 | **不要含 `/`** | `createDocWithMd` 的路径语义会把 `/` 当层级，意外建出父文档 |

> 反常识建议：**不要建太多笔记本**。笔记本是权限与检索的边界，不是分类法。分类交给 MOC + 数据库，检索交给 `sql`。建议 3–5 个：`笔记`、`日记`、`项目`、`归档`、(可选)`剪藏`。

## 4. 采集：入口越少越好

### 4.1 收件箱规则（唯一入口）

- **只允许一个收件箱文档**（例：`收件箱`），所有「还不知道放哪」的东西先扔进去。
- 收件箱有 **SLA：72 小时内清空**。清空方式只有三种：转成原子卡 / 挂到已有 MOC / 删掉。
- 顺手记的碎片走 `daily`，**不要为一句灵感新建文档**。

```bash
S=scripts/siyuan.py
# 碎片先落当天（幂等：已有当天日记就追加）
python3 $S daily -c "- 想法：反链面板其实是一种延迟检索" --notebook <nbId>
# 不确定归属 → 收件箱
python3 $S append <收件箱docId> -c "| 来源 | 一句话 | 待办 |"
```

### 4.2 网页 / 外部素材（剪藏三件套）

1. **抓正文**，不要存整页 HTML；
2. **图片本地化**（防盗链图片直接引用会 403）：
   ```bash
   python3 $S upload <nbId> cover.png      # → assets/cover-2026xxxx.png
   ```
3. **加元信息**：来源 URL、作者、抓取时间、为什么收它。

收完立刻写一句「我为什么收它」。写不出 = 不该收。

### 4.3 幂等（重复采集是最大的熵来源）

建文档前先查重，别靠记忆：

```bash
python3 $S sql "select id,hpath from blocks where type='d' and content like '%知识管理%' limit 10"
python3 $S search "知识管理"        # 内容命中，第二列才是 docId
```

## 5. 每日流（DailyNotes）

### 5.1 当天只做三件事

1. 记碎片（想法/摘录/对话结论），一行一条，带来源；
2. 记**未完成**（明天要接着干的一句话）；
3. 睡前把值得留下的 1–3 条**升级**成原子卡或挂到 MOC。

### 5.2 任务不要只活在日记里

日记里的 `- [ ]` 是**当天的执行清单**，不是待办总账。跨天未完成的任务必须迁出：

- 有明确交付物 → 进「项目」数据库（条目绑定块，见 §8）；
- 只是「想做」→ 进 `MOC·待办池`，每周回顾时决定去留；
- 连续三次被顺延 → 直接删，承认它不重要。

### 5.3 每周回顾（30 分钟，固定动作）

1. 打开本周 7 篇日记，只看 `- [ ]` 与加粗行；
2. 清空收件箱（SLA 兜底）；
3. 挑 3–5 条碎片 → 写成原子卡（用自己的话，**不看原文**）；
4. 给新卡各挂 ≥2 条链接（一条指向已有卡，一条指向 MOC）；
5. 删掉 3 条明确不会再用的东西（**固定做减法**）；
6. 建快照：`python3 $S snapshot create`。

## 6. 原子卡规范（系统的价值所在）

一条卡 = 一个可独立引用的判断。

| 检查项 | 不合格的样子 | 合格的样子 |
| --- | --- | --- |
| 标题 | `读书笔记`、`关于链接的思考` | `链接密度不等于知识密度` |
| 内容长度 | 3000 字大杂烩 | 100–500 字，一段话说清 |
| 视角 | 摘抄原文 | 自己的话 + 「所以呢」 |
| 来源 | 无 | 文末一行 `> 来源：<URL>（<日期>）` |
| 链接 | 0 条 | ≥2 条，且每条附一句关系说明 |
| 可证伪 | 全是「很重要」 | 有边界条件：「在单人库里成立，多人协作会被覆盖」 |

**写作模板（直接抄）**：

```markdown
# <一句断言>

<用自己的话，2–4 段：是什么 / 为什么成立 / 什么情况下不成立>

**所以呢**：<对我的行动意味着什么>

**相关**：((<卡1> "为什么相关"))、((<卡2> "为什么相关"))

> 来源：<URL>（<YYYY-MM-DD>）
```

**判断一条卡是否合格的自测**：关掉原文，对着标题讲 60 秒。讲不顺 = 还没懂，别存。

## 7. 渐进式总结：五层落地（读长文/书时用）

| 层 | 动作 | 在思源里怎么落 |
| --- | --- | --- |
| L0 原文 | 只留来源链接，不存全文 | 卡片末尾 `> 来源：` |
| L1 摘要 | 读完立刻用自己的话写 3–5 条 | 段落列表，每条可被单独引用 |
| L2 加粗 | 第二遍只加粗真正关键的短语 | `**...**` |
| L3 高亮 | 第三遍给能直接用的句子加高亮 | `==...==` |
| L4 精华 | 一句话结论，写进标题或首段 | 标题即断言 |

规则：**每一层都是一次删减**，不是一次追加。允许停在任何一层，但 L1 不能跳过。

## 8. 双链、标签、数据库：什么时候用哪个

| 需求 | 用 | 别用 | 原因 |
| --- | --- | --- | --- |
| 表达「这两条有关，因为…」 | 块引用 `((id "原因"))` + 反链 | 标签 | 标签没有语义，反链有上下文 |
| 表达「属于某个集合」 | 领域/MOC 文档里列出引用 | 深层文件夹 | 一条笔记可以属于多个集合，文件夹不行 |
| 表达「状态/进度/负责人/截止」 | **数据库**（属性 + 视图） | 正文里的文字 | 结构化字段才能筛、能排序、能汇总 |
| 表达「临时主题词」 | 标签 `#待读#` | 建文档 | 标签是**临时脚手架**，用完就撤 |
| 表达「这条卡属于哪个理论体系」 | MOC 文档 + 反向引用 | 标签层级 `#a/b/c` | 层级标签三个月后没人记得规范 |

### 8.1 反链的正确用法：延迟检索

碎片写进日记时**不要**急着归类（归类是决策，决策会阻塞记录）。等真要用的时候，在专题文档里写占位，然后看反链面板把当时的碎片捞出来。

```bash
# 谁引用了这条卡？（写专题文档前先看素材池）
python3 $S backlinks <cardId>
python3 $S backlinks <docId> --by-doc
```

### 8.2 数据库用在「有状态的东西」上

适合：项目、任务、书单、联系人、文章投稿状态、实验记录。
不适合：知识本身（知识用卡 + MOC）。

```bash
# 建一个项目看板：先建文档承载数据库，再加字段
DOC=$(python3 $S create <nbId> "项目看板" | awk '{print $3}')
python3 $S av create $DOC 项目 --keys '[{"name":"状态","type":"select"},{"name":"截止","type":"date"}]'
python3 $S av add-item <avId> 状态=进行中 截止=2026-12-01
```

> 视图（看板/表格/日历）必须在 UI 里配，命令行只保证数据层正确。

## 9. 模板：把「怎么记」变成基础设施

模板降低启动成本。三个模板够用：

- **日记模板**：`## 碎片` / `## 未完成` / `## 今日一条`（后者强制产出）
- **原子卡模板**：见 §6
- **专题/MOC 模板**：`## 一句话定义` / `## 关键判断（引用卡）` / `## 未解问题` / `## 相关`

```bash
python3 $S template ls                              # 列出 data/templates
python3 $S template get 原子卡.md > /tmp/tpl.md      # 先看现状再改
python3 $S file write /data/templates/原子卡.md < card.tpl   # 写模板（W 权限）
python3 $S template render 原子卡.md                 # 渲染（Sprig：now / date / upper…）
python3 $S template save-as <docId> 原子卡 --overwrite        # 把成稿文档反向存成模板
```

模板里的两个坑（实测）：

- `template render` 走 `renderSprig`，**没有文档上下文**：`{{now | date "2006-01-02"}}` 可以，`{{.title}}` 会是 `<no value>`——文档变量只能在 UI 里「插入模板」时解析。要在 markdown 里带标题，就先渲染再自己补，或者干脆不写 `.title`。
- 模板正文里如果含 SiYuan 语法（如 `{{SELECT ...}}`），会被当成 Go action 报 `function "SELECT" not defined`；CLI 会自动退到字面渲染并提示，也可显式 `--escape`。

## 10. 输出流水线：从库到稿

1. **建主题文档**，先写大纲（只有标题，不写内容）；
2. **召回**：对每个大纲节点跑 `search` / `sql` / `backlinks`，把候选块**引用**（不是复制）进文档；
3. **重组**：同一素材可能在多个小节重复出现，合并同类项；
4. **改写**：用自己的话把引用串成句子，删掉引用的原文；
5. **归档**：成稿后把过程中的临时文档移进 `归档`，并在 MOC 里留一条链接。

```bash
python3 $S search "渐进式总结"                      # 找素材
python3 $S sql "select id,hpath from blocks where type='d' and updated > '20261101' order by updated desc limit 20"
python3 $S export md <docId> > draft.md             # 交付/外发
```

## 11. 维护：让库不腐烂的具体动作

### 11.1 体检 SQL（每月跑一次）

```sql
-- 孤儿文档：没有任何块引用它（可能是垃圾，也可能是宝藏）
select d.id, d.hpath, d.updated from blocks d
where d.type='d' and d.id not in (select distinct def_block_id from refs where def_block_id is not null)
order by d.updated asc limit 30;

-- 空文档 / 只有标题的文档
select id, hpath from blocks where type='d' and length < 15;

-- 长期未动的领域文档（该合并或归档了）
select hpath, updated from blocks where type='d' and hpath like '/领域%' order by updated asc limit 20;

-- 一天里建了太多文档（采集失控的信号）
select substr(created,1,8) d, count(*) c from blocks where type='d' group by d having c > 5 order by d desc limit 10;
```

```bash
python3 $S sql "$(cat check.sql)" --json
```

### 11.2 三个时间尺度的动作

| 频率 | 动作 | 产出 |
| --- | --- | --- |
| 每天 10 分钟 | 碎片入日记；清当天的「未完成」 | 日记一条 |
| 每周 30 分钟 | 清收件箱；升级 3–5 张卡；删 3 条；快照 | 卡片增长、库变干净 |
| 每月 60 分钟 | 跑体检 SQL；合并重复 MOC；归档结束的项目 | 结构收敛 |

**只做加法不做减法的库，半年后一定会被弃用。**

## 12. 反模式清单（命中任意一条就要改）

1. **收集者谬误**：疯狂剪藏，从不重读。
2. **为一句灵感建文档**：文档数暴涨，反链失效。
3. **标签当分类法**：`#知识/方法/工具/效率` 层层嵌套，三个月后无人遵守。
4. **标题写成名词短语**：`关于 X 的思考`——不可引用、不可证伪。
5. **复制原文当笔记**：没有自己的话 = 没有理解。
6. **一条笔记塞五个主题**：无法被单独引用。
7. **只连不写**：链接满天飞，没有一句关系说明。
8. **把日记当待办总账**：任务越积越多，最后只敢看不敢开。
9. **没有输出计划**：库只进不出。
10. **从不删**：删不掉的东西 = 没想清楚的东西。

## 13. 与 AI agent 协作的边界

agent 适合做**搬运、查重、体检、格式化**；不适合替你思考。

| 交给 agent | 必须自己来 |
| --- | --- |
| 采集入库、图片本地化、加元信息 | 用自己的话写摘要 |
| 查重、批量打属性、生成索引/目录 | 判断哪条值得留 |
| 跑体检 SQL 并汇总成报告 | 决定合并/删除 |
| 按模板落稿、导出分发 | 论点、结构、措辞 |

给 agent 的硬约束（写进任务里）：
- 新建前先 `sql`/`search` 查重；同名不新建，走 `append`。
- 只 `append` 不 `update`（除非刚读过）。
- 批量/删除前先 `snapshot create`，并列出将改动的清单等确认。
- 不自行提权（`perms set` 必须由人决定）。

## 14. 起步 30 天

| 周 | 只做这些 |
| --- | --- |
| W1 | 建 3 个库（笔记/日记/项目）；定 3 个模板；每天碎片进日记 |
| W2 | 每周回顾跑起来；把本周 3 条碎片写成原子卡（严格按 §6 模板） |
| W3 | 建 1 个 MOC，把已有卡挂上去；开始用 `backlinks` 召回素材 |
| W4 | 用它写一篇 1000 字的东西；跑一次体检 SQL；删 10 条 |

30 天后判断标准：**你能不能在不翻原文的情况下，讲清楚自己库里任意 3 张卡的内容。** 能，方法成立；不能，回到 §6 重写标题。
