# SiYuan 能力边界与限制（详细版）

> 一句话：CLI 是「管理员 token + 笔记本级软权限」的数据层工具，不是安全沙箱，也不是离线数据库。
> SKILL.md 里是精编版，这里是完整清单与对策。

## 1. 硬限制（改代码也绕不过去）

| 限制 | 具体表现 | 对策 |
| --- | --- | --- |
| **权限不是安全边界** | token 是实例管理员凭据，任何拿到 token 的人都能直接调 API；GUARD 只是「防止 agent 误操作」 | token 只放在环境变量/密钥管理；不要把 CLI 暴露给不可信调用方；真要隔离用只读 token 或反向代理白名单 |
| **单工作空间** | 一个内核实例 = 一个工作区（`/siyuan/workspace`），多租户要靠多实例 | 多实例就配多份权限表分组（`~/.config/.siyuan.json` 以 URL 为 key，天然支持） |
| **必须内核在线** | 所有能力（含 SQL、导出、文件）都经内核；内核重启/索引/快照期间接口不可用或阻塞 | 失败先 `ping`；批处理加重试与 `sleep`；长时间任务避开快照窗口 |
| **索引异步** | 写完立刻 SQL 查可能查不到；移动/删除后 `box/path` 要数秒才更新 | 写后不要立刻断言；需要确认就 `read`/`getBlockKramdown` 直读，或等 2–5 秒再查 |
| **无事务、无批量原子操作** | 每条命令一次 HTTP；中途失败 = 部分写入 | 大改动前 `snapshot create`；把变更拆成幂等小步（先查再写） |
| **last-write-wins** | 多 agent / 用户同时编辑同一文档会互相覆盖（`update` 覆盖首块更危险） | 优先 `append`；`update` 只用于自己刚读过的内容；冲突时重读再写 |
| **快照是整库级** | 快照/回滚覆盖所有笔记本，无法只回滚一个库 | 回滚属 D 级操作，需用户明确同意；小范围恢复用 `history`（MCP）或手动改 |
| **导出有损** | `export md` 补 frontmatter 与 `# 标题`、丢 IAL、表格压缩、超级块展开 | 要精确源码用 `block kramdown`；要可读稿用 `export md` |
| **数据库（av）只能走 MCP** | 内核 HTTP API 没有建库端点，参数口径也不一致 | CLI 的 `av *` 已内置 MCP 桥；不要手拼 `/api/av/*` |
| **只读模式** | 系统开启只读后，写类请求被拒（403/相关 msg） | 写失败先查系统设置，别当成权限表问题 |
| **工作区文件是裸操作** | `file write/rm` 直接改 `data/`，不经数据库 | 只用于模板/资源/脚本；不要手改 `data/*.sy`（会破坏索引） |

## 2. 软限制与已知坑

| 场景 | 坑 | 对策 |
| --- | --- | --- |
| 反向代理 / 子路径 | 反代吞 body、路径前缀丢失、SSE/长请求超时 | 用带路径的 `SIYUAN_API_URL`；确认反代不缓冲 `POST`；见 `siyuan-api.md` 反代表 |
| HTTPS 自签 | `URLError: certificate verify failed` | 换可信证书；不要在生产关校验 |
| token 过期/轮换 | 401 | 重新取 token，只更环境变量，不改权限表 |
| 大文本/中文 | 用 `curl` 内联 JSON 易乱码/截断 | 一律走 CLI（`-c`/`-f`/stdin），UTF-8 编码 |
| 标题含 `/` | 被当成多级路径，意外建出父文档 | 标题里避开 `/`，或先建父文档再用 `--to-doc` |
| 图片防盗链 | 微信/知乎图片直接引用会 403 | 先下载到本地 → `upload` → 用返回的 `assets/xxx` 引用 |
| `hpath` vs `path` | `hpath` 是 `/父/子`，`path` 是 `/<id>/<id>.sy`；混用会 404 | 展示用 `hpath`，移动/存储用 `path` |
| 标签重命名 | 空目标等于删除，本部署不支持删标签 | `retag <旧> <新>`，新标签必填 |
| 资源清理 | `asset clean` 删的是「未引用」资源，但索引延迟可能导致误判 | 先 `asset unused` 看清单，再 `--yes`；先 `snapshot create` |
| 同步 | 同步未启用时 `sync status` 返回 `not enabled`；`perform` 是 D 级 | 别把 `perform` 当日常命令 |
| 只读豁免 | `ping`/`notebooks`/`perms` 不审计，会被用来「探测」库 | 这是有意设计，别用它绕权限改数据 |

## 3. 场景可行性速判

| 场景 | 可行性 | 说明 |
| --- | --- | --- |
| 批量整理/重命名/打标签 | ✅ | `sql` 找目标 → 逐条命令；先快照 |
| 定时收集箱投递 | ✅ | `create`/`daily` + 幂等「先查再建」 |
| 仪表盘/日报聚合 | ✅（只读） | `sql` 聚合 + `create` 写结果；注意索引延迟 |
| 文章导入（含图） | ✅ | 下载图 → `upload` → 建文档；先查重 |
| 数据库（表格）维护 | ⚠️ 有限 | 只能通过 MCP 桥；视图布局/关联/汇总等高级字段要人来做 |
| 精细回滚单个文档 | ⚠️ | `snapshot rollback` 是整库；单文档历史用 MCP `history` |
| 实时多人协同编辑 | ❌ | 无锁、无 OT/CRDT 语义 |
| 作为唯一数据源做事务 | ❌ | 无事务、last-write-wins |
| 离线/断网操作 | ❌ | 内核不在就没有数据层 |
| 富文本/复杂排版精修 | ❌ | 只能写 Markdown/块 DOM，最终排版建议人工过一遍 |

## 4. 反模式清单（agent 最容易犯）

1. 没 `read` 就 `update` —— 覆盖整块内容，用户数据直接丢。
2. 用 `sql` 拼写操作 —— `sql` 只放行 `SELECT/WITH`；写必须走专门命令（否则绕过权限语义）。
3. 循环里逐条 `create` 同名文档 —— 不幂等；先 `sql`/`search` 查重。
4. 以为 `search` 返回的是 docId —— 内容命中返回的是块，读文档要用 `docId`（CLI 已同时给出 `blockId`）。
5. 把 `hpath` 当 `path` 传给移动/建库。
6. 权限被拒就自己 `perms set` 提权 —— 必须由用户决定。
7. 大改前不建快照。
8. 在文档 IAL 里写 `title`/`custom-*` 文档属性 —— 无效，必须 `attr set`。
9. 用 `curl` 内联中文 JSON —— 乱码/截断；用 CLI 或文件。
10. 认为「不报错 = 已生效」—— `code:0` 只代表接口收到请求。

## 5. 与内置 MCP / 官方 API 的分工

| 需求 | 首选 | 原因 |
| --- | --- | --- |
| 笔记本级 R/W/D 门禁、审计、权限表 | **CLI** | MCP 没有笔记本级权限模型 |
| 日常增删改查、搜索、SQL、移动、日记 | **CLI** | 一条命令一个动作，退出码可判 |
| 建数据库 / 数据库条目增删 / 单个文档历史 | **CLI 的 `av *` / `mcp`** | HTTP 无端点，等价于 MCP 工具 |
| 技能（skills）管理、`web_search`/`web_fetch` | **`mcp` 子命令** | 纯内核进程内能力 |
| 需要 IDE/客户端原生 MCP 集成 | 官方 MCP | 直接连 `/mcp`，注意它没有笔记本级权限门禁 |

> 结论：CLI 覆盖 MCP 的 29 个工具面（HTTP 直连 + `mcp` 桥），并额外提供权限 GUARD、权限表、退出码契约。

## 6. 部署侧检查清单

- [ ] `SIYUAN_TOKEN` 来自环境变量，不入库、不进文档
- [ ] `SIYUAN_API_URL` 带反代路径前缀时已实测（`ping` 通）
- [ ] 反向代理不缓冲 POST、超时 > 60s（导出/快照较慢）
- [ ] 首次使用已跑 `notebooks` → `perms set` → `perms confirm`
- [ ] 敏感库设为 `NONE`，并确认全局操作被拒
- [ ] 批量/危险操作前 `snapshot create`，并知会用户
- [ ] 自动化任务有重试与超时，不假设索引即时
